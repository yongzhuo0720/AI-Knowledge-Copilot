# 数据库报错处理通用流程

## 报错是常态

数据库在运行过程中会返回各种各样的错误提示。遇到报错时不要慌张，绝大多数情况都有
成熟的排查路径。本文给出通用的处理流程，具体某一条错误码的含义请查阅专门的错误码手册。

## 标准排查步骤

第一步是完整记录错误信息，包括错误文本、发生时间、涉及的表名和执行的语句。
第二步是用应用日志或数据库日志还原当时的上下文，确认是偶发还是必现。
第三步是在测试库上复现，复现不了就先怀疑并发时序或数据差异。

## 常见错误大类

权限类问题表现为访问被拒绝，通常是账号本身或来源主机没有授权。
约束类问题表现为操作被拒绝且提示无法完成，往往与表之间的引用关系有关。
重复类问题表现为写入失败，通常是唯一性要求被违反。
语法与类型类问题通常由 SQL 写法或字段类型不匹配引起，这类问题在开发阶段就能发现。

## 处理原则

不要为了快速恢复服务而跳过约束检查，那会把数据一致性问题推迟到更难排查的时间点。
任何绕过约束的操作都应当记录在案，并在业务低峰期用正确方式补偿。
批量脚本要有幂等性，重复执行不应该产生额外副作用。

## 与事务的关系

多数约束类错误会导致当前事务回滚。因此重试之前必须确认上一笔事务已经结束，
否则会拿到意料之外的中间状态。重试要带退避，避免在数据库已经吃力时继续加压。
