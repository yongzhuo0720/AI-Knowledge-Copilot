# 边缘网关整体架构

## 定位

边缘网关部署在客户现场，向上连接管理平台，向下接入现场设备。
它的核心职责是协议转换、本地缓存和断网续传。本文介绍整体架构与限流机制的设计思路，
具体设备型号的参数对照请查阅型号手册。

## 分层结构

最底层是设备接入层，负责各类现场总线的驱动适配。
中间是数据加工层，完成点位映射、单位换算和量纲统一。
最上层是上行通信层，把处理后的数据按平台协议打包上报。

## 限流设计

网关必须做限流，因为现场设备可能因为故障而高频上报，把上行链路打满。
限流采用令牌桶模型：桶按固定速率补充令牌，请求消耗令牌，令牌耗尽则拒绝。
相比固定窗口计数，令牌桶允许一定程度的突发，更贴近真实流量形态。

## 参数怎么定

桶速率应该略高于正常业务峰值，让正常波动不受影响；又明显低于链路容量，
确保异常流量会被削掉。桶容量决定可以容忍多长时间的突发，通常按峰值持续若干秒来估算。
不同形态的设备因为接口带宽和散热能力不同，参数取值也不同。

## 过载后的行为

被限流的请求应当快速失败并给出明确的重试提示，而不是排队等待，
否则会连带把上游的超时时间拖长。同时上报限流计数，便于平台侧观察现场流量健康状况。

## 升级与回滚

网关固件升级要保证断电安全：要么完整写入新分区，要么保持旧分区可用。
升级窗口建议安排在业务低峰期，并预留足够的回滚时间。
