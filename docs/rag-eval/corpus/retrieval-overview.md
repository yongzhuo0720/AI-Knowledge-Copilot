# 检索技术总览

## 检索解决什么问题

检索的目标是从大量文档里找出与用户提问最相关的一小部分，再交给生成模型组织答案。
检索质量直接决定最终答案质量：检索不到，模型再强也只能编。

## 两类检索思路

第一类是字面匹配，把文档和查询都看成词的集合，谁包含的查询词多、包含的词越稀有，
谁就更相关。这类方法可解释性强，对术语和编号敏感，但不懂同义词和改写。

第二类是语义匹配，把文本映射成稠密向量，用向量距离衡量语义接近程度。
这类方法能处理换一种说法提问的情况，但会丢失精确的字面信息。

## 两类的取舍

只用字面匹配，遇到用户用完全不同的措辞提问时会漏召。
只用语义匹配，遇到必须精确匹配的编号或术语时会排错。
真实业务里两种需求同时存在，所以主流方案都是把两路结果合起来。

## 融合与再排序

两路结果的分数往往不在同一量纲上，直接相加需要先做归一化，而归一化会引入偏差。
一种常见做法是只看名次不看分数，把两路的名次做倒数后相加，从而绕开量纲问题。

拿到融合后的候选之后，还可以再做一次更精细的排序。这一阶段的特点是让查询和候选
放在一起比较，而不是各自独立编码，因此精度更高、代价也更大，通常只对少量候选执行。

## 评估方式

检索效果必须量化。常用做法是准备一批带标准答案的问题，分别看正确文档有没有被召回、
以及排在第几位。没有量化指标的调优只能算碰运气。
