### 2.1 文档处理

前端上传 → Java 校验登录、知识库所在工作空间成员身份、文件扩展名 → 生成 `kb/{knowledgeBaseId}/{uuid}/{filename}` → 写 MinIO → MySQL 登记 `UPLOADED` → Python 提交解析任务 → 下载原文、解析结构块 → 按结构边界打包切片 → Embedding → Milvus → 更新任务状态。默认目标片长 800 字符，只有超长单块才使用重叠 120 的滑窗。

任务具有重试、心跳、过期恢复及可选 MySQL 持久化；Compose 开启任务存储，Python 本地默认关闭。Java 文档状态与 Python 任务状态为不同记录，查询刷新时同步，不能假设跨服务同时提交。重新解析使用 `replace_existing=true`；删除依次尝试向量和对象清理，再删除 MySQL 文档记录。

同内容再次上传会生成新 UUID 对象键，没有内容哈希去重的业务承诺。没有独立的原文就地编辑链路，更新主要通过再次上传或重新解析体现，测试不能假设存在尚未实现的文档版本管理。

入口：[KnowledgeService.java](D:/ai_project/AI_agent/backend/src/main/java/com/aicopilot/knowledge/KnowledgeService.java:88)、[indexing.py](D:/ai_project/AI_agent/ai-service/app/indexing.py:165)。

### 2.2 检索与回答

提问 → Java 验证知识库访问权与会话所有权 → 先保存用户消息 → 取最近最多 20 条历史 → Python 检索 → 编号资料拼接上下文 → 模型生成 → Java 保存助手消息及来源 → 返回结果。普通会话支持 SSE；Agent 接口返回最终 HTTP 结果，工作台展示返回的步骤，并非实时步骤流。

检索支持纯向量、BM25、混合 RRF、本地标识符提权，可配置远端 Rerank 和查询改写；默认混合检索，查询改写默认关闭。问答固定取 5 条，引用返回对象键、内容、分数等；没有完整的稳定片段 ID、页码与原文坐标定位协议。混合/RRF 分数也不能统一解释为向量相似度。

缺少聊天密钥会返回说明性模板；缺少 Embedding 密钥会使用哈希向量。因此服务可响应并不证明真实语义检索和生成可用。哈希与真实向量共用固定集合，切换模型时缺少模型版本隔离，需要单独验证重建策略。

入口：[answering.py](D:/ai_project/AI_agent/ai-service/app/answering.py:8)、[ConversationService.java](D:/ai_project/AI_agent/backend/src/main/java/com/aicopilot/conversation/ConversationService.java:119)。
